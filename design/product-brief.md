# Fanfic Atlas 介面重設計：產品簡述

| 欄位 | 內容 |
| --- | --- |
| 工作語言 | zh-TW |
| 階段 | Prototype |
| 產品方向 | 將跨平台同人搜尋由「裝飾性首頁」重設為可快速判讀搜尋意圖、來源狀態與收藏脈絡的探索工作區。 |
| 專案／決策責任人 | 使用者（Fanfic Atlas 專案擁有者） |
| 發行者 | Fanfic Atlas 專案 |

## 問題假設

> 同人讀者在跨平台尋找 CP 或作品時，現有首頁的視覺訊號過多，會增加判讀搜尋輸入、來源健康狀態與結果相關性的成本；若搜尋區、狀態區、結果卡與閱讀工具改為明確的連續工作流，讀者應能更快理解目前查詢的範圍與下一步。

| 邊界 | 內容 |
| --- | --- |
| 操作者／受益者 | 使用 Fanfic Atlas 搜尋、篩選、收藏與管理 CP 詞庫的同人讀者。 |
| 機器角色 | 搜尋 Adapter、CP 轉譯器與本機閱讀清單；其不產生或偽造作品資料。 |
| 受影響者 | 外部平台與創作者；介面需清楚保留來源、狀態與原站連結。 |
| 排除群體 | 無法公開索引、需要登入或不在已註冊來源範圍內的平台讀者。 |
| 可做 | 前端排版、視覺 token、資訊架構、空／錯誤狀態、互動回饋、可及性與測試。 |
| 不可做 | 不改 Adapter 搜尋語意、API 契約、資料庫 schema、收藏／詞庫 localStorage key，亦不加入偽造作品或使用者評價。 |
| 需要詢問 | 任何品牌名稱更動、平台擴充、資料儲存策略、登入／公開內容政策或外部發佈。 |

## 證據與限制

| 訊號 | 來源 | 層級 | 解讀與反證 |
| --- | --- | --- | --- |
| 使用者要求「重新設計目前的介面」 | 專案擁有者的直接請求 | T1 | 支持將現有布局視為不足；但尚無真實任務完成率或訪談資料，不能聲稱已驗證可用性提升。 |
| 首頁可見大型裝飾英雄、搜尋、狀態、結果與閱讀工具並列 | 目前預覽與程式碼 | T1 | 支持減少首屏競爭；但視覺喜好為擁有者的人類判斷。 |

## 已知風險與回復

| 風險 | 回復性 | 擁有者 | 回復方式 |
| --- | --- | --- | --- |
| 新排版降低既有操作辨識 | 高 | 專案擁有者 | 以 checkpoint 還原；保留既有事件、資料模型與測試選擇器。 |
| 過度弱化來源狀態 | 高 | 專案擁有者 | 將來源健康卡維持為搜尋結果前的固定資訊區。 |
